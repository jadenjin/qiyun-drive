# 并发一致性约定

修改请求统一使用 PostgreSQL Serializable 事务。权限读取、状态修改、配额和审计属于同一次提交；响应正文及 Cookie 在提交成功后才发送。处理器内部事务作为保存点使用。冲突及死锁返回 `409 concurrent_change`，客户端重新读取状态后重试；上传确认对这一错误最多自动重试两次。

采用可串行化事务和冲突重试来实现报告要求的一致性，而不是依赖每个处理器各自约定的行锁顺序。跨目录、权限继承链和后台任务涉及的行集合会变化，不能把单个目录的固定加锁顺序当作整个系统的保证。

上传创建先锁定空间配额再预留容量。完成请求锁定上传会话，仅生成一次发布任务。Worker 在复制对象之后重新进入事务，锁定上传会话、复核当前权限，再一起更新正式对象、会话、空间计量和审计。每次尝试使用不同正式路径，旧执行不能覆盖已发布文件；任务心跳和结果更新必须匹配领取时的执行次数。

过期清理先将仍可写的会话标记为 expired，再中止分片及删除暂存数据；分片中止失败必须重试。清理和用户取消最终都会锁定上传会话，只有持有预留的状态才能释放配额。失败发布已释放的预留不会再次扣减。清除回收站使用持久任务认领，已认领节点不能恢复。

验证证据包括数据库锁屏障同步的相向移动、删除目录与新增子目录；双 Worker 失效租约重新领取；上传排队后撤销 ACL；过期分片清理及用户取消已过期上传；清除认领与恢复边界。测试断言目录无环、已删目录下无活子节点、发布审计仅一次、配额与正式资产一致。
